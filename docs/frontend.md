## フロントエンド仕様（MVP）

CashPilot のフロントエンドは Next.js (App Router) + React + TypeScript を用いた SPA 風構成とする。  
プロダクトの**目的**（[docs/README.md](./README.md) および [database.md](./database.md) に合わせる）は次の4つである。

- **家計管理**: 収支・口座・カテゴリの登録・一覧・編集を直感的に操作できるUIを提供する。
- **キャッシュフロー分析**: 月次・日次の集計や残高推移をグラフ・一覧で表示する。
- **シミュレーション**: 将来残高や目標達成時期の試算結果を入力〜結果表示まで一貫して扱える画面を提供する。
- **将来マルチユーザー対応**: 認証済みユーザー単位でデータがスコープされる前提で画面を設計し、のちのマルチユーザー拡張時にも改修が最小限で済むようにする。

MVP では「シンプルな導線で、家計管理・分析・シミュレーションがすぐに使えること」を最優先とする。

### 2. 各画面の要件（MVP）

#### 2-1. サインアップ／ログイン画面

- **目的**
  - ユーザーを認証し、個人ごとの収支・シミュレーションデータへアクセスできるようにする。
- **主な要素**
  - メールアドレス入力欄
  - パスワード入力欄
  - 「サインアップ」「ログイン」のタブもしくは切り替えボタン
  - 「ログイン」完了後はダッシュボードへ遷移
- **MVP前提**
  - バリデーションは最低限（メール形式／パスワード長など）
  - パスワードリセットは将来拡張でも可（MVPでは簡易リンク表示程度）

#### 2-2. ダッシュボード画面

- **目的**
  - ログイン直後に「現在の状況」と「将来イメージ」の概要を一目で把握できるようにする。
- **表示内容（MVP）**
  - 上部: 現在の残高（口座別または全体。取引の集計。初期残高は口座の設定または残高調整用取引で表現する想定で [backend.md](./backend.md) と合わせる）
  - 中央: 将来キャッシュフローの簡易グラフ（例: 今から 1〜3 年の残高推移）
  - 下部:
    - 今月の収支サマリー（収入合計／支出合計／収支差分＝取引の `SUM(amount)`）
    - 直近の取引一覧（5〜10 件程度）
- **操作**
  - 「収支を入力する」ボタン → 収支入力画面へ
  - 「シミュレーションを調整する」ボタン → シミュレーション画面へ

#### 2-3. 収支入力画面（取引登録）

- **目的**
  - 取引（transactions）を 1 件ずつ登録する。DB 設計（[database.md](./database.md)）に合わせ、口座・カテゴリ・金額（符号付き）・発生日時・メモを扱う。
- **入力項目（MVP）**
  - 口座: プルダウン（当該ユーザーの accounts 一覧。type: cash / bank / credit）
  - カテゴリ: プルダウン（収入用・支出用の categories。種別は金額の正負と整合させる）
  - 金額: 収入は正の数値、支出は負の数値で入力（または「収入/支出」選択＋絶対値で入力し、API 送信時に符号を付与）
  - 発生日時（`occurred_at`）: デフォルトは現在日時
  - メモ（任意）
- **補足**
  - 繰り返し取引は DB v1 に `recurring_transactions` がないため MVP では対象外。将来拡張で対応する。
- **UI方針**
  - 入力フォームは 1 カラムでシンプルにし、モバイルでも使いやすくする。直近の登録履歴を同画面下部に表示する。

#### 2-4. シミュレーション設定 & 結果画面

- **目的**
  - 「Xヶ月後／X年後に○○をしたい」といった目標と、現在〜将来の収支前提をもとに、残高推移を可視化する。
- **入力（設定）エリア**
  - シミュレーション期間: 例) 1年 / 3年 / 5年（プリセット + カスタム年月）
  - 目標イベント（任意）:
    - タイトル（例: 引っ越し、海外旅行）
    - 目標時期（年月 or 日付）
    - 必要金額
  - 将来前提（予定的収支）の調整（MVPでは簡易な形で）:
    - 毎月の本業収入（固定額）
    - 毎月の副業収入（固定額）
    - 毎月の固定費（家賃・サブスクなどを合算した金額の簡易入力）
    - 毎月の目標貯蓄額
- **結果表示エリア**
  - 残高推移グラフ（折れ線）
    - 現在残高〜シミュレーション終了時まで
    - 目標イベントのタイミングにマーカー表示
  - 数値サマリー:
    - シミュレーション期間内の最小残高
    - 目標時点での予測残高（必要金額とのギャップ）
    - 年間／月間の平均収支 など
- **MVP制約**
  - シナリオは 1 つのみ（「現状シナリオ」）を扱う。
  - 目標イベントは 0〜1 件を想定（複数イベントは将来拡張）。

#### 2-5. プロフィール／基本設定画面

- **目的**
  - 口座・カテゴリ・目標の管理と、シミュレーションで使う前提の確認・入力を行う。
- **項目（MVP）**
  - 口座の一覧・追加・編集（口座名・種別: cash / bank / credit）。残高は取引の集計で表示するため、初期残高はバックエンド方針に合わせる（口座に `initial_balance` を持たせるか、残高調整用取引で表現するか）。
  - カテゴリの一覧・追加・編集（収入用 / 支出用）。
  - 目標（goals）の一覧・追加・編集（名前・目標金額・期限）。シミュレーション画面と連携する。
  - 必要に応じて、デフォルトのシミュレーション期間などはフロントのデフォルト値でよい（DB に持たない想定）。

### 3. ナビゲーションとレイアウト

- **ヘッダー**
  - ロゴ（またはアプリ名）
  - サイドバー開閉ボタン
  - ログイン中ユーザーのメール表示
- **サイドバー**
  - ナビゲーションリンク（ダッシュボード／収支入力／シミュレーション／設定）
  - ログアウトボタン
- **レイアウト**
  - PC: ヘッダー + サイドバー + コンテンツ
  - モバイル: ハンバーガーメニュー or 画面下部タブナビゲーションを検討（MVPではヘッダー簡易メニューでも良い）

---

### 4. 状態管理・データ取得方針（MVP）

- **状態管理**
  - Next.js App Router + React の標準 Hooks（`useState`, `useEffect`, `useContext`）を基本とし、  
    グローバルなユーザー情報・設定値はコンテキストで管理。
  - 複雑な状態管理ライブラリ（Redux 等）は MVP では導入しない前提。
- **データ取得**
  - 認証後に取得する主なデータ: ユーザー情報、口座一覧、カテゴリ一覧、目標一覧、取引一覧（期間・口座・カテゴリでフィルタ可能）、キャッシュフロー集計、シミュレーション実行結果。いずれも [backend.md](./backend.md) の API から取得。
  - 通信は REST API（JSON）を前提とし、fetch or Axios などで実装。

---

### 5. UI/UX 方針（MVP）

- **入力ハードルを下げる**
  - 必須項目を最小限にし、「とりあえず金額と日付だけ入れれば動く」体験を重視。
- **グラフの見やすさ**
  - 折れ線グラフは、現在〜将来の残高推移が直感的に分かるデザインとする。
  - 目標イベントがある場合は、そのポイントをアイコンや色で強調。
- **フィードバック**
  - 収支登録後にトーストやバナーで「登録しました」を表示。
  - API エラー時は簡易なエラーメッセージを表示し、再試行しやすくする。
