## CashPilot ドキュメント概要（MVP方針）

CashPilotは、以下の**4つの目的**を満たすWebアプリケーションである。本ドキュメントでは、MVP段階での全体方針と大まかな仕様の方向性を示す。

### 1. 目的（プロダクトゴール）

- **家計管理**: 収入・支出・口座・カテゴリを登録し、日々の収支を記録・把握する。
- **キャッシュフロー分析**: 登録した取引から月次・日次のキャッシュフローを集計し、残高推移や平均生活費などを可視化する。
- **シミュレーション**: 現在の残高と予定収支をもとに、将来の残高推移や「Xヶ月後に○○をしたい」といった目標の達成可否を試算する。
- **将来マルチユーザー対応**: 設計時点から「1ユーザー = 1オーナー」のスコープでデータを保持し、のちの世帯・共有などへの拡張を可能にする。

上記を前提とした**ゴールイメージ**:
  - 毎月の収入・支出・貯蓄額を登録すると、将来のキャッシュフロー（残高推移）がグラフで見える。
  - 「現在の預金残高○円」「来月以降のクレジット支払い○円」「サブスク固定費○円／月」「来月以降の本業収入○円・副業収入○円」といった“ほぼ確定している予定収支”を入力すると、「Xヶ月後に○○（例: 引っ越し／旅行／大きな買い物 など）をするには、どの程度の貯蓄ペースが必要か／いつ頃なら実行しやすいか」をシミュレーションできる。
  - 副業や支出削減などのシナリオを変えて、将来残高の変化を比較できる（MVPでは単一シナリオから開始）。

### 2. 対象ユーザーと利用シーン

- **対象ユーザー**
  - 給与所得＋副業など複数の収入源を持つ個人
  - 家計簿アプリは使っている／続かなかったが、「将来の残高イメージ」をざっくり掴みたい人
- **主な利用シーン**
  - 最初の初期設定や、月ごと・数ヶ月ごとにライフプランや貯蓄計画を大きく見直すタイミングで、「大まかな前提（収入・固定費・目標時期など）」を設定する。
  - 日々の支出も簡易に記録していくことで、月次の変動や小さな出費の積み上がりが将来の残高にどう効いてくるかを把握する。
  - 転職や副業開始、大きな支出（引越し／車／結婚など）の前後で、影響をシミュレーションしたいとき。

### 3. MVPスコープ（機能の範囲）

MVPでは、以下の機能にフォーカスする（詳細は [database.md](./database.md)・[backend.md](./backend.md) に合わせる）。

- **家計管理**
  - 口座（accounts）・カテゴリ（categories）の登録・編集。取引（transactions）の登録・一覧・編集。目標（goals）の登録・一覧。
  - 取引は「口座・カテゴリ・金額（収入は正・支出は負）・発生日時・メモ」を登録。入力項目は最小限に。
- **キャッシュフロー分析**
  - 取引の集計により、月次・日次のキャッシュフロー、残高推移、平均生活費などを一覧・グラフで表示。
- **シミュレーション**
  - 現在残高（取引の集計）と予定収支をもとに、一定期間の残高推移を計算。目標（goals）の達成時期・不足額の試算。

将来的には以下も検討するが、MVPでは必須としない。

- 複数シナリオ比較（現状 vs 副業開始後 vs 支出削減後 など）
- 繰り返し取引（recurring_transactions）の登録・予測への反映
- 自動連携（銀行／クレカAPI）やレシート取り込み
- 共有機能（パートナー・世帯と共有など）

### 4. 非機能要件（MVP時点）

- **パフォーマンス**
  - 個人利用を前提とした少量データを想定し、シンプルな構成とする。
  - グラフ描画・シミュレーションは、1〜数秒以内に応答。
- **セキュリティ**
  - 認証はメール＋パスワード or 外部 ID プロバイダを想定。
  - パスワードなどセンシティブ情報はバックエンドで扱わず、認証基盤に委譲。
- **可用性**
  - 個人プロダクトとして、24/7 の厳密な SLA は設けない。

### 5. 全体アーキテクチャ方針（概要）

- **フロントエンド**
  - Next.js（App Router）を採用。画面（ダッシュボード、口座・カテゴリ・取引・目標、シミュレーション）、認証連携、グラフ描画を担当。
- **バックエンド**
  - Go（Gin）で REST API。口座・カテゴリ・取引・目標の CRUD、キャッシュフロー集計、シミュレーション計算、認証トークン検証を担当。
- **データベース**
  - PostgreSQL。users / accounts / categories / transactions / goals を保存（[database.md](./database.md) 参照）。
- **インフラ・デプロイ**
  - ローカル開発は Docker Compose で一括起動。本番デプロイは実装が進んでから検討（[infra.md](./infra.md) 参照）。
